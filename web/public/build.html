Partner API + SDK

Build with VRE

On-chain proof of who won. Send participants and a formula, the VRE operator runs the draw on devnet, anyone verifies it from the transaction signature.

How it works

Three steps. One request. One replay path.

You send one HTTP request; the operator commits your rules, waits for future Solana slots and settles the draw on-chain. The canonical program binds only rules approved by its admin key, so draws run through the API; verification needs nothing.

1
commit

Send participants

Participants, a formula and the number of winners go in one request with your partner key. The rules are committed on-chain before any randomness exists.

$ curl -X POST …/api/partner/draw
2
resolve

Winners from future slots

prepare_rng_v2 fixes three slots 8, 16 and 24 slots ahead; once they exist, settle_rng_v2 picks the winners from their hashes. The request returns in 12–45 seconds.

→ prepare_rng_v2 · settle_rng_v2
3
verify

Share & verify

You get a signature. Paste it at /verify, run vre verify or call verifyOutcome(). Anyone can replay the same outcome from public RPC data.

$ vre verify --sig … → MATCH / OK

Partner Draw API

One POST request. Outcome committed on-chain.

No SDK required. Send participants and a formula — get back a transaction signature and a public replay URL. One request takes 12–45 seconds because it waits for future Solana slots. One draw per 10 seconds per key.

Use cases

Committed rules. Single or multi-winner outcomes.

Same request shape: participants and a formula in, a signature anyone can replay out.

Raffle

weighted_random. One winner from a committed weighted participant list.

Rewards Selection

weighted_random with several winners. Replay returns the full ordered outcome_ids.

Trading Competition

rank_desc. Signed scores and stable input order produce deterministic top-N winners.

Prediction Market

closest_to. Replay includes the committed target, signed scores and stable order.
